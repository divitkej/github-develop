# The bar every repo of mine has to clear

A repo that does not clear this bar is either fixed or made private. Nobody is
impressed by nineteen public repos when four of them are empty.

## Required

1. **README.md** that answers, in this order:
   - What this does, in one sentence a non-engineer understands
   - A screenshot or a short demo, if it has a visible output
   - How to install and run it, copy-pasteable
   - What is not finished yet, honestly
2. **LICENSE**. MIT unless there is a reason. Without one, legally nobody may
   use your code, which defeats the point of publishing it
3. **.gitignore** appropriate to the language. No `node_modules`, no `.env`,
   no `__pycache__`, no `.DS_Store` in the history
4. **Description and topics** set on the repo page. The sidebar fields, not
   just the README. This is what makes a repo findable
5. **No secrets**, anywhere in the history

## Strongly recommended

- A `requirements.txt`, `package.json`, or equivalent so the thing installs
- At least one test, and a CI workflow that runs it
- Releases with tags once the project is usable, starting at `v0.1.0`
- An `examples/` folder or a usage section with real input and output

## The README opening line test

Read your own first line as if you were a stranger. If it says "A project
built using React and Node.js", rewrite it. That describes the tools, not the
thing. Say what it does: "Syncs a WhatsApp group's member list to a Google
Sheet every hour."

## Pinned repos

Six slots on the profile. Order them by strength, strongest first. Rules:

- No coursework dumps in the pinned six unless the coursework is genuinely
  substantial
- No forks unless you made meaningful changes
- No repo you would not want to be asked about in an interview

Everything else stays unpinned. It still counts, it just does not lead.
